# Чаша дня

**Адреса:** <https://romanhrytsko.github.io/daybowl/>

Local-first PWA, що показує, наскільки заповнений кожен день тижня і скільки часу лишається для себе. Специфікація — [daybowl_spec.md](daybowl_spec.md).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run test:run   # юніт- і сценарні тести
npm run build      # статика + service worker у dist/
```

## Структура

```text
src/
  domain/      чисті функції: типи, dayStats/weekStats, повтори, копія тижня (+ тести)
  data/        Dexie-схема, репозиторії, стартовий набір, експорт/імпорт JSON
  state/       useWeek / useDay (useLiveQuery), uiStore (Zustand + хеш-маршрути)
  components/  BowlSvg, TemplateChips, ActivityRow, SizePicker
  screens/     Тиждень, День, Підсумок, Шаблони, Налаштування, Онбординг
  i18n/        uk.ts — усі тексти
```

## Деплой

Кожен push у `main` запускає [.github/workflows/deploy.yml](.github/workflows/deploy.yml): lint → тести → build → GitHub Pages. Якщо тести падають, сайт не оновлюється. Версія збірки (git SHA) видна в Налаштуваннях.

Одноразове налаштування: репозиторій **public**, Settings → Pages → Source: **GitHub Actions**.

Нові функції роби в гілках: мердж у `main` = реліз. `localhost:5173` і Pages — різні сховища, тож локальні експерименти не зачіпають справжніх даних. Щоб тестувати на реальних даних, експортуй їх на Pages і імпортуй локально.

## Дані

Дані зберігаються лише в IndexedDB браузера й прив'язані до адреси сайту. Захист:

1. **Встанови як застосунок**, бо Safari стирає дані сайтів, які не відкривали 7 днів.
   - macOS: Chrome / Edge — іконка «Встановити» в адресному рядку; Safari — Файл → Додати в Dock.
   - iPhone: Safari → Поділитися → «На початковий екран». Встановлений застосунок має **окреме** сховище від вкладки Safari, тому онбординг проходь уже в ньому.
2. **Постійне сховище**: при кожному запуску застосунок запитує `navigator.storage.persist()`, а статус видно в Налаштуваннях.
3. **Резервна копія**: Налаштування → Експортувати JSON. Якщо копії не було понад 7 днів, на екрані Тиждень з'явиться нагадування. Зберігай файл в iCloud Drive / Google Drive.

Якщо зміниться адреса сайту (перейменування репозиторію, власний домен), там буде порожнє сховище. Спершу зроби експорт, потім імпорт.

### Правило міграцій Dexie

1. `version(1).stores(SCHEMA_V1)` більше ніколи не змінюється.
2. Новий індекс або таблиця — це `version(2).stores({...}).upgrade(tx => ...)`.
3. Нові неіндексовані поля робимо опційними, версію схеми не піднімаємо.
4. Тест «база, створена схемою v1, відкривається поточною DaybowlDB без втрат» (`src/data/data.test.ts`) має проходити.
5. Перед деплоєм зі зміною схеми — експорт даних.
