# Чаша дня — специфікація POC

Nov 21, 2026 · @Roman

## Огляд і мета

**Чаша дня** — веб-застосунок, який показує, наскільки заповнений кожен день тижня і скільки в ньому лишається часу для себе. Це не to-do список, а доповнення до нього: він міряє завантаженість, а не відстежує виконання.

**Проблема.** На питання «скільки часу ти приділяєш собі» важко відповісти, бо цей час ніде не видно. Справи записані в календарях і to-do, а вільний простір — ні.

**Концепція.** Кожен день — це чаша. Кожна справа — шар рідини свого кольору. Що більше справ, то вище рівень. Коли справ забагато, чаша переповнюється і надлишок виливається через край. Порожнє місце над рідиною — потенційний час для себе.

**Цілі POC**

- За 1–2 хвилини спланувати день, за 5 хвилин — тиждень.
- З одного погляду на тиждень бачити перевантажені й вільні дні.
- Отримати одне число: скільки годин на тиждень заплановано для себе.
- Перевірити, чи метафора чаші справді допомагає вирішувати «від чого відмовитися».

**Не-цілі POC**

- Не календар із точним часом початку і кінця.
- Не трекер звичок і не система нагадувань.
- Без акаунтів, синхронізації, спільного доступу та мобільного застосунку.

## Ключові поняття

Одиниця виміру — хвилини, але користувач вводить їх розмірами S/M/L/XL, а не числами.

| Поняття | Визначення |
| --- | --- |
| Чаша | Один календарний день зі своїм об'ємом і справами |
| Об'єм (capacity) | Скільки хвилин день містить, за замовчуванням 16 год (час без сну). Можна змінити на конкретний день |
| Шар (Activity) | Одна справа в чаші. Висота = тривалість, колір = категорія |
| Категорія | Тип справи, який створює користувач: рутина, робота, спорт, навчання, відпочинок… |
| Тип категорії (kind) | `obligation` — обов'язок, `self` — час для себе, `neutral` — решта |
| Вільний простір | Об'єм мінус сума справ, якщо більше нуля |
| Переповнення | Сума справ мінус об'єм, якщо більше нуля. Показується як рідина, що виливається |
| Час для себе | Сума справ типу `self` — головна метрика застосунку |
| Енергія (опційно) | Вплив справи на сили: −1 виснажує, 0 нейтрально, +1 наповнює |

**Розміри справ:** S = 30 хв, M = 60 хв, L = 120 хв, XL = 240 хв. У деталях справи можна ввести точні хвилини, але це не обов'язково.

## Сценарії та функціональні вимоги

P0 — без цього POC не має сенсу; P1 — бажано в POC; P2 — після POC.

**Ключові сценарії**

1. **Перше налаштування (≤ 3 хв).** Користувач отримує набір стандартних категорій, за бажанням перейменовує їх, вказує об'єм дня і додає 2–3 повторювані справи (напр. робота пн–пт XL×2).
2. **Планування тижня (≤ 5 хв).** Відкриває тиждень — повторювані справи вже в чашах. Додає разові тапом по шаблону, прибирає зайве.
3. **Рішення про баланс.** Бачить, що четвер переповнений на 1,5 год, а в п'ятницю є місце. Перетягує справу на інший день або видаляє її.
4. **Рефлексія.** В кінці тижня дивиться підсумок: скільки годин для себе, скільки переповнених днів, порівняння з минулим тижнем. Може показати це психологу.

## UX і екрани

Головне правило: додати справу — це один тап, змінити — не більше двох. Усе, що вимагає думати або рахувати, робить застосунок.

**Принципи легкого заповнення**

- **Розміри замість хвилин.** S/M/L/XL достатньо для оцінки завантаженості; точність не потрібна.
- **Шаблони-чипи.** Під чашею ряд чипів у кольорах категорій. Тап — справа «падає» в чашу з типовим розміром. Спочатку ті, що найчастіше використовувалися.
- **Повтори та копія тижня.** Тиждень заповнюється сам; користувач тільки коригує.
- **Пряма маніпуляція.** Перетягнути край шару — змінити розмір; перетягнути шар на іншу чашу — перенести на інший день.
- **Без обов'язкових полів.** Справа = назва + категорія + розмір; усе інше має значення за замовчуванням.
- **Без почуття провини.** Переповнення — це сигнал, а не помилка: без червоних попереджень, тільки м'який підпис «+1,5 год понад об'єм».
- **Вільний час видно.** Порожнє місце в чаші підписане годинами («вільно 3 год»).

**Екрани POC**

| Екран | Що на ньому | Основні дії |
| --- | --- | --- |
| Тиждень (головний) | 7 чаш в ряд, під кожною день і вільні години; вгорі години для себе за тиждень | Відкрити день, перетягнути справу між днями, скопіювати тиждень, гортати тижні |
| День | Велика чаша, список справ, ряд чипів-шаблонів, об'єм дня | Додати тапом, змінити розмір, видалити, змінити об'єм |
| Шаблони і категорії | Список категорій з кольорами, шаблони з правилами повтору | Створити, змінити, архівувати |
| Підсумок тижня | Години для себе, час по категоріях, динаміка за 4 тижні | Перегляд |
| Налаштування | Об'єм за замовчуванням, початок тижня, експорт / імпорт | Змінити, зберегти копію |

## Модель даних

Зберігаються лише п'ять сутностей; рівень чаші, вільний час і підсумки рахуються на льоту. Усі id — UUID, дати — рядки `YYYY-MM-DD` у локальному часовому поясі користувача. Кожна сутність має `createdAt` / `updatedAt` (ISO) для майбутньої синхронізації.

```ts
type CategoryKind = 'obligation' | 'self' | 'neutral';
type Size = 'S' | 'M' | 'L' | 'XL';
type Energy = -1 | 0 | 1;

export const SIZE_MINUTES: Record<Size, number> = { S: 30, M: 60, L: 120, XL: 240 };

interface Base {
  id: string;
  createdAt: string;
  updatedAt: string;
}

export interface Category extends Base {
  name: string;          // "Робота"
  color: string;         // "#4F7CFF"
  kind: CategoryKind;    // 'self' рахується як час для себе
  order: number;
  archived: boolean;
}

export interface ActivityTemplate extends Base {
  title: string;
  categoryId: string;
  defaultMinutes: number;          // з Size або власне число
  energy?: Energy;
  recurrence?: {
    weekdays: number[];            // 1 = пн … 7 = нд
    startDate: string;
    endDate?: string;
  };
  usageCount: number;              // для сортування чипів
  archived: boolean;
}

export interface Activity extends Base {
  date: string;                    // '2026-11-23'
  title: string;                   // копія з шаблону, можна змінити
  categoryId: string;
  minutes: number;
  energy?: Energy;
  templateId?: string;
  source: 'manual' | 'recurrence' | 'copy';
  status: 'planned' | 'done' | 'skipped';
  order: number;                   // порядок шарів знизу вгору
  deletedAt?: string;              // tombstone: видалений повтор не генерується знову
}

export interface DayConfig extends Base {
  date: string;                    // унікальний ключ
  capacityMinutes?: number;        // немає = береться з Settings
  note?: string;
}

export interface Settings {
  defaultCapacityMinutes: number;  // 960 = 16 год
  weekStartsOn: 1;                 // понеділок
  schemaVersion: number;
}
```

**Похідні розрахунки** (чисті функції в `domain/`, покриті юніт-тестами):

```ts
export interface DayStats {
  capacity: number;
  total: number;
  fill: number;            // total / capacity, > 1 = переповнення
  freeMinutes: number;
  overflowMinutes: number;
  selfMinutes: number;
  byCategory: Record<string, number>;
}

export function dayStats(
  acts: Activity[], capacity: number, cats: Map<string, Category>,
): DayStats {
  const live = acts.filter(a => !a.deletedAt && a.status !== 'skipped');
  const total = live.reduce((s, a) => s + a.minutes, 0);
  const byCategory: Record<string, number> = {};
  let selfMinutes = 0;
  for (const a of live) {
    byCategory[a.categoryId] = (byCategory[a.categoryId] ?? 0) + a.minutes;
    if (cats.get(a.categoryId)?.kind === 'self') selfMinutes += a.minutes;
  }
  return {
    capacity, total, fill: total / capacity,
    freeMinutes: Math.max(0, capacity - total),
    overflowMinutes: Math.max(0, total - capacity),
    selfMinutes, byCategory,
  };
}
```

- `weekStats` — сума `DayStats` за 7 днів + кількість днів з `fill > 1`.
- `materializeRecurrences(weekStart)` — при відкритті тижня створює `Activity` з `source: 'recurrence'` для кожної пари (шаблон, дата), якої ще немає. Запис із `deletedAt` теж рахується як «є», тож видалений повтор не повертається. Операція ідемпотентна.
- `copyWeek(from, to)` — копіює живі справи з `source !== 'recurrence'` (повтори створяться самі) з `source: 'copy'`.

**Індекси IndexedDB (Dexie):** `activities: id, date, [date+order], templateId`; `dayConfigs: date`; `categories: id, order`; `templates: id, usageCount`; `settings` — один запис.

## Архітектура і стек

POC — local-first SPA без бекенду. Уся логіка чаші живе в чистих функціях домену, тому синхронізацію чи мобільний клієнт можна додати пізніше без переписування UI.

| Хостинг | Vercel / Netlify / Cloudflare Pages | Статика, деплой з git |

**Візуалізація чаші (`BowlSvg`)**

- Контур чаші — `path`; він же `clipPath` для вмісту.
- Шари — стопка прямокутників знизу вгору за `order`; висота шару = `minutes / capacity × висота чаші`. Оскільки чаша ширша вгорі, висоту рахуємо по об'єму, а не лінійно (або для POC робимо чашу з прямими стінками).
- Верхній край кожного шару — синусоїда з невеликою амплітудою, анімована зсувом фази.
- Переповнення: рідина вище краю обрізається, а по зовнішній стінці стікає потік і краплі; їх розмір пропорційний `overflowMinutes`.
- Компонент отримує лише `DayStats` + список шарів і нічого не знає про сховище. Тому його можна буде замінити на Canvas з metaballs або 3D на react-three-fiber.

## Якість, критерії приймання і етапи

**Нефункціональні вимоги**

- **Швидкість:** тиждень відкривається за < 300 мс; анімація рідини — 60 fps на ноутбуці середнього рівня.
- **Офлайн:** усе працює без мережі; PWA з можливістю встановити на екран телефона.
- **Приватність:** дані лише в браузері, без аналітики та трекерів; експорт у JSON — єдиний спосіб винести їх.
- **Адаптивність:** від 360 px; на телефоні тиждень — горизонтальний скрол чаш.
- **Доступність:** колір не єдиний носій змісту (назва шару при наведенні / фокусі); `prefers-reduced-motion` вимикає хвилі; керування з клавіатури.
- **Мова:** українська; тексти винесені в один файл для майбутньої локалізації.

**Критерії приймання POC**

- [ ] Новий користувач заповнює перший тиждень менш ніж за 5 хвилин.
- [ ] Додати справу з шаблону — 1 тап; змінити розмір — не більше 2 дій.
- [ ] День, де сума справ більша за об'єм, показує переповнення і скільки саме зайвого.
- [ ] Тижневий екран показує години для себе, їх сума збігається з сумою справ типу `self`.
- [ ] Видалений повтор не з'являється знову після перезавантаження.
- [ ] Дані зберігаються після закриття браузера; експорт + імпорт відновлюють той самий стан.
- [ ] Особисте випробування: 3 тижні щоденного використання і відповідь психологу цифрою.

**Етапи**

1. **Домен і дані.** Типи, `dayStats`, повтори, Dexie-репозиторії, юніт-тести.
2. **День.** Додавання тапом, чипи шаблонів, проста чаша-стовпчик.
3. **Тиждень і рідина.** 7 SVG-чаш, хвилі, переповнення, drag & drop між днями.
4. **Легкість.** Повтори, копія тижня, онбординг зі стартовими категоріями.
5. **Підсумки.** Тижневий підсумок, експорт / імпорт, PWA.
6. **Після POC.** Енергія, 3D-чаша, акаунти і синхронізація, мобільний застосунок.

**Відкриті питання**

- Як рахувати незапланований вільний час: як час для себе чи окремо?
- Чи входить сон у чашу, чи об'єм — це лише час без сну?
- Чи потрібна ціль «часу для себе на тиждень», чи це вже створить тиск?
- Чи має енергія впливати на об'єм шару (виснажлива година «важча»)?
